# SpiralCore

تطبيق Android أصلي لإدارة الروابط كقواقع رقمية شخصية. الواجهة والمصادقة والتكامل مع نظام Android مكتوبة بـKotlin وJetpack Compose. تُحفظ الروابط والتصنيفات وبذور مظهر القواقع محليًا عبر Room/SQLite؛ لا يوجد خادم أو مزامنة أو إذن إنترنت.

## الأمن والخصوصية

- يستخدم التطبيق Android BiometricPrompt وبيانات اعتماد قفل الجهاز؛ لا يحتفظ برمز PIN خاص بالتطبيق.
- تُحجب لقطات الشاشة عبر FLAG_SECURE ويُعطّل النسخ الاحتياطي.
- روابط المستخدم تُعالج محليًا، ويقبل المُدقّق HTTP/HTTPS فقط، ويرفض بيانات الاعتماد داخل العنوان وأحرف التحكم والمدخلات الطويلة والمنافذ غير الصالحة.
- قاعدة البيانات مشفّرة باستخدام SQLCipher؛ يُغلّف مفتاحها بمفتاح AES-GCM داخل Android Keystore. عند ترحيل قاعدة قديمة، يُتحقق من النسخة المشفرة ثم يحاول التطبيق حذف ملف SQLite القديم وملفات WAL/SHM. لا يمكن ضمان المحو الجنائي من ذاكرة Flash، وقد يفشل التنظيف؛ عندها تُسجّل محاولة لإعادته.
- مراجعة أمنية مصدرية ليست اختبار اختراق مستقلًا، ولا تضمن غياب كل الثغرات.

## المتطلبات

- Android Studio حديث أو JDK 17 مع Android SDK 35.
- Android 9 (API 28) أو أحدث.
- Gradle Wrapper المضمّن في المستودع.

## البناء والاختبارات

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebug
./gradlew assembleRelease
```

تعمل GitHub Actions على تشغيل اختبارات JVM والبناء والتحليل الأمني. ملف Release الناتج من البناء الآلي غير موقّع ما لم يُضبط توقيع آمن عبر بيئة CI.

## الأمن قبل الإصدار

راجع `SECURITY_REVIEW.md` و`docs/ENCRYPTION_THREAT_MODEL.md` للقيود وبوابات الإصدار. يلزم التحقق من نجاح CI على آخر commit، واختبار ترحيل قاعدة تحتوي بيانات فعلية على أجهزة Android حقيقية، والتحقق من سياسة النسخ الاحتياطي والاستعادة، وتوقيع الإصدار عبر أسرار بيئة CI قبل النشر.
