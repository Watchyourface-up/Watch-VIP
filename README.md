# TAPORA

تطبيق Android أصلي لتسجيل الصوت محليًا باستخدام Kotlin وJetpack Compose وMediaRecorder، مع خدمة تسجيل أمامية وفهرسة التسجيلات عبر Room.

منطق التسجيل مفصول إلى `MediaRecorderEngine` و`RecordingFileStore` و`RecordingStateMachine`. الحالات الصريحة هي `Ready` و`Recording` و`Saving` و`Error`: لا يبدأ تسجيل ثانٍ، ولا يقبل الإيقاف المكرر، ولا تعلن الواجهة نجاح الحفظ قبل اكتمال نقل الملف وفهرسته في Room.

## البناء محليًا

يتطلب JDK 17 وAndroid SDK 35. شغّل `./gradlew testDebugUnitTest` للاختبارات و`./gradlew assembleDebug` لإنشاء APK تجريبي. يتطلب بناء Release الموقّع إعداد متغيرات `TAPORA_KEYSTORE_FILE` و`TAPORA_KEYSTORE_PASSWORD` و`TAPORA_KEY_ALIAS` و`TAPORA_KEY_PASSWORD`؛ لا تضع ملف المفتاح أو كلمات مروره في المستودع.

## تسجيل مستمر وخصوصية

ابدأ التسجيل من واجهة TAPORA بينما التطبيق ظاهر، وامنح إذن الميكروفون. بعدها تستطيع إطفاء الشاشة؛ يبقى التسجيل في خدمة أمامية ذات إشعار دائم يتضمن زر إيقاف. الملفات تحفظ في مساحة التطبيق الخاصة بأسماء UUID، وتُكتب أولًا بامتداد `.m4a.part` ثم تُنقل ذريًا إلى `.m4a` بعد نجاح `stop()` والتحقق من الحجم. يفشل المسار بوضوح عند نقص المساحة أو فشل الكتابة أو الملف الفارغ، ويحرر مورد الميكروفون ويحذف الملف الجزئي. عند فتح التطبيق تُزال فهارس Room التي تشير إلى ملفات مفقودة.

اكتشاف ضغطتي رفع الصوت مفصول عن محرك التسجيل ويُختبر ككاشف توقيت مستقل؛ الكاشف لا يبدأ التسجيل بنفسه. لا يدّعي TAPORA أن أحداث زر الصوت تصل عند قفل الشاشة أو إطفائها: يجب اختبار ذلك فعليًا على الجهاز المستهدف وتوثيق الطراز وإصدار Android والسجلات. لا يضمن `AccessibilityService` أو أي إذن عام هذه الأحداث، ولا يستخدم التطبيق وسائل تحايل. البديل المدعوم عند تعذر الاختصار هو بدء التسجيل قبل إطفاء الشاشة أو تثبيت لوحة TAPORA في Quick Settings.

## الاختبارات والتحقق

اختبارات الوحدة تغطي انتقالات الحالات، منع البدء/الإيقاف المكرر، عدم إعلان الحفظ قبل اكتماله، وحدود نافذة ضغطتي رفع الصوت. نجاح البناء أو اختبارات الوحدة لا يثبت وصول أحداث الأزرار أو استمرار التسجيل في الخلفية. يلزم على الجهاز المستهدف التحقق من منح إذن الميكروفون، إشعار الخدمة، قفل الشاشة، إطفاء الشاشة، قيود البطارية وDoze، انقطاع التسجيل، والمساحة المنخفضة، مع الاحتفاظ بسجل الاختبار الفعلي.

## الإصدارات

عند دفع وسم مثل `v1.0.0`، يشغّل GitHub Actions الاختبارات، ويبني APK Release موقّعًا، ثم ينشئ GitHub Release ويرفق APK. يتطلب المسار أسرار المستودع `TAPORA_KEYSTORE_BASE64` و`TAPORA_KEYSTORE_PASSWORD` و`TAPORA_KEY_ALIAS` و`TAPORA_KEY_PASSWORD`. يتوقف إصدار الوسم بوضوح إذا كان أي سر مفقودًا.
